Objects & data shapes

Eleven utilities for reading, reshaping and comparing nested data: get and set by path, flatten, deep equal, deep clone, nested filtering, list to tree, grouping, deep merge, immutable updates and rendering JSON as HTML. Each has the core idea, a tested solution, the edge cases that break naive versions, and where to take it next.

Almost all of them are the same recursive walk with a different decision at each node. Three ideas carry most of the weight.

Walk by shape

At every node, decide: primitive, array, plain object, or something special like a Date, Map or class instance. Recurse into the containers, act on the rest. Most bugs come from treating a Date or null as a plain object.

Used in: flatten, deep equal, deep clone, filter, merge, JSON to HTML

Paths as key lists

Turn 'a.b[0].c' into ['a', 'b', 0, 'c'] once, then walk the list. Numbers mean arrays. Block __proto__ whenever input can write keys.

Used in: get, set, setIn, unflatten, immutable update

Remember what you've seen

A WeakMap or Set of visited objects stops infinite loops on cycles and keeps shared references shared. Copy only the path you change and reuse the rest.

Used in: deep equal, deep clone, remove cycles, list to tree, setIn, update

Get a value by path

      
Seen in interviews atAmazonSDE2 practice setSDE2 problem set 4Paths as key lists

    

    
  

  
Parse the path into a list of keys once, then step down one key at a time, stopping safely when something along the way is missing.

  

    
Approach
  1. Accept a string like a.b[0].c or an array of keys. Bracket parts become numbers or quoted keys, so a["b.c"] reaches a key that contains a dot.
  2. Walk the keys. If the current value is null or undefined, return the default.
  3. At the end, return the default only when the value is undefined, not when it is falsy.

    
Edge cases
  • A price of 0 or an empty string is a real value; || defaultValue would hide it.
  • Splitting on dots alone breaks keys that contain dots, and indexes written as [0].
  • A null in the middle of the path must not throw.

      
Go further
  • Support negative indexes like items[-1] for the last item.
  • Return every match for wildcard paths like seats[*].price.
  • How does optional chaining (a?.b?.[0]) compare when the path is known at write time?

  

  
Show solution (try it yourself first)
    
// 'a.b[0].c', 'a[b.c]', ['a', 'b', 0] are all accepted.
function toPath(path) {
  if (Array.isArray(path)) return path;
  const keys = [];
  String(path).replace(/[^.[\]]+|\[(?:(-?\d+)|(["'])(.*?)\2)\]/g, (match, index, quote, quoted) => {
    keys.push(index !== undefined ? Number(index) : quote ? quoted : match);
    return '';
  });
  return keys;
}

function get(obj, path, defaultValue) {
  let cur = obj;
  for (const key of toPath(path)) {
    if (cur == null) return defaultValue;
    cur = cur[key];
  }
  return cur === undefined ? defaultValue : cur;
}

  






  

    

      
Set a value by path, mutable and immutable

      
Seen in interviews atCourse JS trackPaths as key lists

    

    
  

  
Walk the path creating any missing container on the way. The immutable version copies only the objects along the path and shares everything else.

  

    
Approach
  1. Reuse the same path parser as get.
  2. For each key except the last, create a container if one is missing: an array if the next key is a number, otherwise an object.
  3. Assign the value at the last key.
  4. Immutable version: recurse down the path and rebuild each level with a shallow copy, putting the new child in place. Untouched siblings keep their old references, which is what lets React skip re-rendering them.

    
Edge cases
  • Reject __proto__, constructor and prototype in paths. Otherwise set({}, "__proto__.isAdmin", true) changes every object in the app.
  • Setting index 3 of an empty array leaves holes at 0 to 2. That matches lodash, but say so.
  • If something along the path is a string or number, decide whether to replace it with a container or throw.

      
Go further
  • Use the object lab: run setIn and see which branches are copied and which are shared.
  • Write unset(obj, path) and an immutable updateIn(obj, path, fn).
  • How do Immer and Redux Toolkit let you write mutating code and still get this sharing?

  

  
Show solution (try it yourself first)
    
// Mutating version creates missing containers: an array when the next key is a number.
const UNSAFE = new Set(['__proto__', 'constructor', 'prototype']);

function set(obj, path, value) {
  const keys = toPath(path);
  if (keys.some((k) => UNSAFE.has(k))) throw new Error('Unsafe key in path');
  let cur = obj;
  keys.forEach((key, i) => {
    if (i === keys.length - 1) { cur[key] = value; return; }
    if (cur[key] === null || typeof cur[key] !== 'object') cur[key] = typeof keys[i + 1] === 'number' ? [] : {};
    cur = cur[key];
  });
  return obj;
}

// Immutable version: copies only the containers along the path; everything else is shared.
function setIn(obj, path, value) {
  const keys = toPath(path);
  if (keys.some((k) => UNSAFE.has(k))) throw new Error('Unsafe key in path');
  const go = (node, i) => {
    if (i === keys.length) return value;
    const key = keys[i];
    const base = node !== null && typeof node === 'object' ? node : typeof key === 'number' ? [] : {};
    const copy = Array.isArray(base) ? base.slice() : { ...base };
    copy[key] = go(base[key], i + 1);
    return copy;
  };
  return go(obj, 0);
}

  






  

    

      
Flatten a nested object to dot keys, and back

      
Seen in interviews atAdobeImpact AnalyticsSDE2 practice setWalk by shape

    

    
  

  
Walk the object carrying the path so far. At each leaf, write the joined path as a key. Unflatten is just set for each key.

  

    
Approach
  1. Recurse into plain objects, and into arrays when indexes should become path segments.
  2. Treat everything else as a leaf: primitives, null, Dates, class instances.
  3. Keep empty objects and arrays as leaves, otherwise they vanish and the round trip loses data.
  4. Unflatten: split each key on the separator, turn digit-only segments into numbers, and call set.

    
Edge cases
  • A Date flattened as an object turns into nothing, because it has no own enumerable keys.
  • Keys that already contain the separator make the result ambiguous. Choose a separator the data can't contain, or escape it.
  • Digit-only object keys like {"2026": …} come back as array indexes. Mention it as a known limitation.

      
Go further
  • Accept a custom separator and an option to stop at a maximum depth.
  • Where is this used in practice? Form libraries, analytics event properties, and translation files.

  

  
Show solution (try it yourself first)
    
const isPlainObject = (v) => v !== null && typeof v === 'object' && Object.getPrototypeOf(v) === Object.prototype;

function flatten(obj, { separator = '.', arrays = 'index' } = {}) {
  const out = {};
  const walk = (value, prefix) => {
    const isArr = Array.isArray(value);
    const descend = isPlainObject(value) || (isArr && arrays === 'index');
    const entries = descend ? Object.entries(value) : [];
    if (!descend || entries.length === 0) {
      if (prefix) out[prefix] = value; // keep {} and [] as leaves so nothing is lost
      return;
    }
    for (const [k, v] of entries) walk(v, prefix ? prefix + separator + k : k);
  };
  walk(obj, '');
  return out;
}

function unflatten(flat, { separator = '.' } = {}) {
  const out = {};
  for (const [key, value] of Object.entries(flat)) {
    set(out, key.split(separator).map((k) => (/^\d+$/.test(k) ? Number(k) : k)), value);
  }
  return out;
}

  






  

    

      
Deep equal

      
Seen in interviews atImpact AnalyticsTekion (Staff)Remember what you've seen

    

    
  

  
Two values are equal if they are the same primitive, or the same kind of container with equal contents. The edge cases are what make it hard.

  

    
Approach
  1. Start with Object.is, which treats NaN as equal to itself and 0 and -0 as different.
  2. Different prototypes mean different kinds of thing: an array is never equal to an object with numeric keys.
  3. Handle Date, RegExp, Map and Set explicitly, then compare own keys, including symbols, for everything else.
  4. Track pairs already being compared in a Map, so cyclic structures terminate.

    
Edge cases
  • {a: 1} and {a: 1, b: undefined} have different keys. Count keys, don't just look up values.
  • JSON.stringify comparison fails on key order, undefined, Dates, Maps and cycles.
  • Sets of objects need a deep match per element, which is quadratic. This version compares Set members by reference and says so.

      
Go further
  • Return the path of the first difference, not just true or false.
  • Make a shallow-equal version and explain where React uses it (memo, dependency arrays).
  • Why do useEffect dependency arrays use Object.is rather than deep equality?

  

  
Show solution (try it yourself first)
    
function deepEqual(a, b, seen = new Map()) {
  if (Object.is(a, b)) return true; // handles NaN, and -0 vs 0 as different
  if (typeof a !== 'object' || typeof b !== 'object' || a === null || b === null) return false;
  if (Object.getPrototypeOf(a) !== Object.getPrototypeOf(b)) return false;

  // cycles: if we are already comparing this pair, assume equal for now
  if (seen.get(a) === b) return true;
  seen.set(a, b);

  if (a instanceof Date) return a.getTime() === b.getTime();
  if (a instanceof RegExp) return String(a) === String(b);
  if (a instanceof Map) {
    if (a.size !== b.size) return false;
    for (const [k, v] of a) if (!b.has(k) || !deepEqual(v, b.get(k), seen)) return false;
    return true;
  }
  if (a instanceof Set) {
    if (a.size !== b.size) return false;
    for (const v of a) if (!b.has(v)) return false; // primitives and same references
    return true;
  }
  const ka = Reflect.ownKeys(a), kb = Reflect.ownKeys(b);
  if (ka.length !== kb.length) return false;
  for (const k of ka) {
    if (!Object.prototype.hasOwnProperty.call(b, k) || !deepEqual(a[k], b[k], seen)) return false;
  }
  return true;
}

  






  

    

      
Deep clone with cycles, and removing cycles

      
Seen in interviews atFancodeSDE2 problem set 8 (remove cycles)Remember what you've seen

    

    
  

  
Copy recursively, but record each original object and its copy in a WeakMap first. A second visit returns the existing copy, which keeps cycles and shared references intact.

  

    
Approach
  1. Return primitives as they are.
  2. If the object is already in the WeakMap, return its copy.
  3. Create the right empty container (array, Map, Set, or an object with the same prototype), store it in the WeakMap, then fill it.
  4. To remove cycles instead, walk with a set of current ancestors and delete any property pointing back to one of them.

    
Edge cases
  • Register the copy before recursing, or a self-reference recurses forever.
  • Removing every repeated reference is wrong: two siblings pointing to the same object is not a cycle. Track ancestors on the current path only.
  • JSON.parse(JSON.stringify(x)) drops undefined, functions and Dates, and throws on cycles.

      
Go further
  • When would you use the built-in structuredClone, and what can it not copy? (Functions, DOM nodes, class prototypes.)
  • Make a cycle-safe JSON.stringify that writes "[Circular]".

  

  
Show solution (try it yourself first)
    
function deepClone(value, seen = new WeakMap()) {
  if (value === null || typeof value !== 'object') return value;
  if (seen.has(value)) return seen.get(value); // keep shared and circular references intact
  if (value instanceof Date) return new Date(value);
  if (value instanceof RegExp) return new RegExp(value.source, value.flags);
  if (value instanceof Map) {
    const m = new Map(); seen.set(value, m);
    value.forEach((v, k) => m.set(deepClone(k, seen), deepClone(v, seen)));
    return m;
  }
  if (value instanceof Set) {
    const s = new Set(); seen.set(value, s);
    value.forEach((v) => s.add(deepClone(v, seen)));
    return s;
  }
  const copy = Array.isArray(value) ? [] : Object.create(Object.getPrototypeOf(value));
  seen.set(value, copy);
  for (const key of Reflect.ownKeys(value)) copy[key] = deepClone(value[key], seen);
  return copy;
}

// Remove properties that point back to an ancestor (true cycles); shared siblings are kept.
function removeCycles(obj) {
  const ancestors = new WeakSet();
  const walk = (node) => {
    ancestors.add(node);
    for (const key of Object.keys(node)) {
      const v = node[key];
      if (v === null || typeof v !== 'object') continue;
      if (ancestors.has(v)) delete node[key];
      else walk(v);
    }
    ancestors.delete(node);
  };
  if (obj !== null && typeof obj === 'object') walk(obj);
  return obj;
}

  






  

    

      
Filter a nested object

      
Seen in interviews atAmazonSDE2 practice setWalk by shape

    

    
  

  
Recurse into containers and keep leaves that pass the test. A branch that ends up empty is removed, so the result contains only paths that lead to matches.

  

    
Approach
  1. For each entry, recurse if it is a plain object or array; otherwise run the test on the leaf.
  2. Pass the key and the full path to the test, so callers can filter on location as well as value.
  3. Return undefined for a branch with nothing kept, and skip it in the parent.
  4. For arrays, push kept items so the result has no holes.

    
Edge cases
  • Decide whether an empty object in the input counts as a match; here it is dropped.
  • Compacting arrays changes indexes. If indexes matter, keep holes or return paths instead.
  • Never mutate the input; build a new structure.

      
Go further
  • Return the matching paths instead of a filtered copy (the basis of a JSON search box).
  • Filter by key rather than value: remove every key named password before logging.

  

  
Show solution (try it yourself first)
    
// Keep leaves that pass the test; drop branches that end up empty.
function filterDeep(obj, test, path = []) {
  const out = Array.isArray(obj) ? [] : {};
  let kept = 0;
  for (const [key, value] of Object.entries(obj)) {
    const here = [...path, key];
    if (isPlainObject(value) || Array.isArray(value)) {
      const child = filterDeep(value, test, here);
      if (child !== undefined) { Array.isArray(out) ? out.push(child) : (out[key] = child); kept++; }
    } else if (test(value, key, here)) {
      Array.isArray(out) ? out.push(value) : (out[key] = value);
      kept++;
    }
  }
  return kept ? out : undefined;
}

  






  

    

      
Turn a flat list with parent IDs into a tree

      
Seen in interviews atAmazon (entity relations)Remember what you've seen

    

    
  

  
Index every item by ID in a Map first, then attach each item to its parent in one pass. That is O(n), with no searching inside loops.

  

    
Approach
  1. Build a Map from ID to a copy of the item with an empty children array.
  2. For each node, look up its parent. Attach it there, or treat it as a root if there is no parent or the parent is missing.
  3. Check that every node is reachable from a root. Any that aren't are part of a cycle.

    
Edge cases
  • Items can arrive in any order: a child before its parent must still work, which the two-pass approach handles.
  • A filter inside a loop to find children is O(n²) and slow for thousands of categories.
  • Copy the items rather than adding children to the caller's objects.

      
Go further
  • Go the other way: tree back to a flat list with depth, for rendering an indented list.
  • Render it as a nested checkbox tree or file explorer (common machine-coding follow-ups).
  • Find the path from the root to any node, for breadcrumbs.

  

  
Show solution (try it yourself first)
    
function listToTree(items, { id = 'id', parentId = 'parentId' } = {}) {
  const nodes = new Map(items.map((item) => [item[id], { ...item, children: [] }]));
  const roots = [];
  for (const node of nodes.values()) {
    const parent = node[parentId] == null ? null : nodes.get(node[parentId]);
    if (parent) parent.children.push(node);
    else roots.push(node); // no parent, or the parent is missing: treat as a root
  }
  // a cycle (A -> B -> A) would leave nodes unreachable from any root
  const reached = new Set();
  const mark = (n) => { if (reached.has(n)) return; reached.add(n); n.children.forEach(mark); };
  roots.forEach(mark);
  if (reached.size !== nodes.size) throw new Error('Cycle in parent links');
  return roots;
}

  






  

    

      
Group an array of objects and aggregate values

      
Seen in interviews atLivespaceAmazon (aggregate input values)Walk by shape

    

    
  

  
Build a composite key from the grouping fields, keep running totals per key in a Map, then turn each group into one output row.

  

    
Approach
  1. Make the group key with JSON.stringify of the key values, so values containing your separator can't collide.
  2. Keep count, sum, min and max per metric while scanning once.
  3. Derive averages at the end from sum and count, never by averaging averages.
  4. A Map keeps groups in first-seen order, which makes the output stable.

    
Edge cases
  • Joining keys with | makes "a|b" + "c" and "a" + "b|c" the same group.
  • Non-numeric or missing values: decide whether they count as zero or are skipped, and be consistent.
  • Using a plain object as the group store is risky with a key like __proto__; a Map is not.

      
Go further
  • Add a pivot: cities as rows, categories as columns.
  • Stream it: update totals as rows arrive instead of from a full array.
  • Compare with Object.groupBy and Map.groupBy, now built into JavaScript.

  

  
Show solution (try it yourself first)
    
// groupAggregate(rows, ['city', 'category'], { tickets: 'sum', price: 'avg' })
function groupAggregate(rows, keys, metrics) {
  const groups = new Map();
  for (const row of rows) {
    const k = JSON.stringify(keys.map((key) => row[key])); // safe composite key
    let g = groups.get(k);
    if (!g) {
      g = { key: Object.fromEntries(keys.map((key) => [key, row[key]])), count: 0, sums: {}, mins: {}, maxs: {} };
      groups.set(k, g);
    }
    g.count++;
    for (const m of Object.keys(metrics)) {
      const v = Number(row[m]) || 0;
      g.sums[m] = (g.sums[m] || 0) + v;
      g.mins[m] = Math.min(g.mins[m] ?? Infinity, v);
      g.maxs[m] = Math.max(g.maxs[m] ?? -Infinity, v);
    }
  }
  return [...groups.values()].map((g) => {
    const out = { ...g.key, count: g.count };
    for (const [m, how] of Object.entries(metrics)) {
      out[m] = how === 'sum' ? g.sums[m] : how === 'avg' ? g.sums[m] / g.count : how === 'min' ? g.mins[m] : g.maxs[m];
    }
    return out;
  });
}

  






  

    

      
Deep merge two or more objects

      
Seen in interviews atCourse JS trackWalk by shape

    

    
  

  
Copy keys from each source in order. When both sides hold plain objects, merge them recursively; otherwise the later value wins.

  

    
Approach
  1. Loop over the sources left to right.
  2. If the source value is a plain object, merge it into the target's value (or into a new object if the target's value isn't one).
  3. Replace arrays and everything else, and skip undefined so a missing value doesn't erase a default.
  4. Skip __proto__ and friends when the source comes from user input or JSON.

    
Edge cases
  • Merging config parsed from JSON without the key check is a classic prototype pollution bug.
  • Arrays: replace, concatenate, or merge by index? Each is valid; pick one and document it.
  • Class instances and Dates should be copied as values, not merged key by key.

      
Go further
  • Make it non-mutating by starting from a fresh object.
  • Add a custom merge function per key, as in lodash mergeWith.
  • Where does this show up in frontend work? Theme overrides, feature-flag defaults, form initial values.

  

  
Show solution (try it yourself first)
    
// Later sources win; plain objects merge recursively; arrays and other values replace.
function deepMerge(target, ...sources) {
  for (const src of sources) {
    if (!isPlainObject(src)) continue;
    for (const key of Object.keys(src)) {
      if (UNSAFE.has(key)) continue; // never let input write to prototypes
      const s = src[key], t = target[key];
      if (isPlainObject(s)) target[key] = deepMerge(isPlainObject(t) ? t : {}, s);
      else if (s !== undefined) target[key] = Array.isArray(s) ? s.slice() : s;
    }
  }
  return target;
}

  






  

    

      
Immutability helper with $set, $push, $merge and friends

      
Seen in interviews atCourse JS trackRemember what you've seen

    

    
  

  
The update spec mirrors the shape of the state. Walk both together, apply a command where one appears, and copy only the containers on the way to a change.

  

    
Approach
  1. If the spec at this level is a command ($set, $apply, $push, $unshift, $splice, $merge, $unset), return the new value it produces.
  2. Otherwise, for each key in the spec, recurse into the state at that key.
  3. If no child changed, return the original state object itself, so equality checks can skip work.
  4. Shallow-copy arrays and objects only when a child really changed.

    
Edge cases
  • Returning a new object even when nothing changed forces needless re-renders in React.
  • A spec key that is not in the state should create it, as { deep: { new: { $set: 1 } } } does.
  • Reject unsafe keys, because specs can come from untrusted input.

      
Go further
  • Add $toggle for booleans and $remove for array items matching a test.
  • Compare with Immer: what does writing mutating code inside produce buy you?

  

  
Show solution (try it yourself first)
    
// update(state, { cart: { items: { $push: [x] } }, user: { $merge: { name } } })
function update(state, spec) {
  if (spec === null || typeof spec !== 'object') throw new Error('Spec must be an object');
  if ('$set' in spec) return spec.$set;
  if ('$apply' in spec) return spec.$apply(state);
  if ('$push' in spec) return [...state, ...spec.$push];
  if ('$unshift' in spec) return [...spec.$unshift, ...state];
  if ('$splice' in spec) {
    const copy = state.slice();
    spec.$splice.forEach((args) => copy.splice(...args));
    return copy;
  }
  if ('$merge' in spec) return { ...state, ...spec.$merge };
  if ('$unset' in spec) {
    const copy = { ...state };
    spec.$unset.forEach((k) => delete copy[k]);
    return copy;
  }
  let changed = false;
  const copy = Array.isArray(state) ? state.slice() : { ...state };
  for (const key of Object.keys(spec)) {
    if (UNSAFE.has(key)) throw new Error('Unsafe key in spec');
    const next = update(state == null ? undefined : state[key], spec[key]);
    if (!Object.is(next, copy[key])) { copy[key] = next; changed = true; }
  }
  return changed ? copy : state; // nothing changed: keep the same reference
}

  






  

    

      
Render JSON as HTML (and as DOM nodes)

      
Seen in interviews atMetaWalk by shape

    

    
  

  
Each node is a tag, props and children, like the objects React.createElement returns. Render the tree recursively, escaping text and attributes and refusing anything that could run script.

  

    
Approach
  1. Strings and numbers become escaped text; arrays render each item; null and false render nothing.
  2. Validate the tag name and attribute names against simple patterns before using them.
  3. Map className to class and htmlFor to for, write true as a bare attribute, and skip false and null.
  4. Close void elements like img and input without children.
  5. The DOM version creates nodes with createElement and setAttribute, which escapes text for you.

    
Edge cases
  • Unescaped text turns <img onerror=…> in an event title into script.
  • Drop on* props and javascript: URLs, as in the object lab example.
  • An attribute name built from input can break out of the tag; validate names, not just values.
  • 0 is valid content and should render, unlike false.

      
Go further
  • Render to DOM, then diff two trees and patch only what changed (a tiny virtual DOM).
  • Accept components: if type is a function, call it with props and render the result.
  • How does this relate to the JSON-driven UI and server-driven UI questions?

  

  
Show solution (try it yourself first)
    
// { type: 'div', props: { className: 'card' }, children: ['Hi', { type: 'b', children: 'there' }] }
const VOID = new Set(['br', 'hr', 'img', 'input', 'meta', 'link']);
const escapeHtml = (s) => String(s).replace(/[&<>"']/g, (c) => ({ '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;' })[c]);

function toHtml(node) {
  if (node == null || node === false) return '';
  if (typeof node === 'string' || typeof node === 'number') return escapeHtml(node);
  if (Array.isArray(node)) return node.map(toHtml).join('');
  const { type, props = {}, children } = node;
  if (!/^[a-z][a-z0-9-]*$/.test(type)) throw new Error('Invalid tag: ' + type);
  const attrs = Object.entries(props)
    .filter(([name, v]) => v != null && v !== false && !/^on/i.test(name)) // no inline event handlers
    .map(([name, v]) => {
      const attr = name === 'className' ? 'class' : name === 'htmlFor' ? 'for' : name;
      if (!/^[a-zA-Z][\w-]*$/.test(attr)) throw new Error('Invalid attribute: ' + name);
      if ((attr === 'href' || attr === 'src') && /^\s*javascript:/i.test(v)) return '';
      return v === true ? ` ${attr}` : ` ${attr}="${escapeHtml(v)}"`;
    })
    .join('');
  if (VOID.has(type)) return `<${type}${attrs}>`;
  return `<${type}${attrs}>${toHtml(children)}</${type}>`;
}

// The DOM version, like React.createElement but for real nodes
function toDom(node, doc = document) {
  if (node == null || node === false) return doc.createTextNode('');
  if (typeof node === 'string' || typeof node === 'number') return doc.createTextNode(String(node));
  if (Array.isArray(node)) {
    const frag = doc.createDocumentFragment();
    node.forEach((n) => frag.appendChild(toDom(n, doc)));
    return frag;
  }
  const el = doc.createElement(node.type);
  for (const [name, v] of Object.entries(node.props || {})) {
    if (v == null || v === false || /^on/i.test(name)) continue;
    el.setAttribute(name === 'className' ? 'class' : name === 'htmlFor' ? 'for' : name, v === true ? '' : String(v));
  }
  if (node.children != null) el.appendChild(toDom(node.children, doc));
  return el;
}
